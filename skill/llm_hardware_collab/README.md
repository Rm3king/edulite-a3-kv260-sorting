# Skill：让大模型智能体参与真实硬件开发的提示词工作流

## 适用范围

用编码智能体（本项目使用 Claude Code 与 Codex，并结合 AMD Ross 完成 HLS 开发）开发带执行机构的嵌入式系统：智能体能读写代码、跑测试、通过 SSH 查询板卡，但机械臂、电源等物理动作必须由人确认。

## 内容

| 文件 | 类型 | 作用 |
|---|---|---|
| `boundary_rules_template.md` | 规则模板 | 放在仓库根目录作为智能体的常驻上下文：授权边界、不可覆盖的事实、答复格式 |
| `evidence_first_writing_rules.md` | 规则模板 | 文档与报告的写作规则：结论与数据先行、数字只来自原始文件、成功率与延迟的口径 |
| `hardware_run_checklist.md` | 检查清单 | 每次上机前后智能体与操作员各自要做的事 |

## 使用方法

1. 把 `boundary_rules_template.md` 改名为智能体读取的项目说明文件（如 `CLAUDE.md`、`AGENTS.md`），按项目填写“授权边界”和“不可覆盖的事实”两节。
2. 每次出现“模型结论与实测不一致”，把已核实的结果和证据入口写进“不可覆盖的事实”，作为后续会话的约束与检查项。
3. 写文档前把 `evidence_first_writing_rules.md` 交给智能体；所有数字用占位符从原始数据渲染，不手填。
4. 上机前后按 `hardware_run_checklist.md` 逐项执行。

## 失效条件

- 规则只约束智能体的行为，不替代硬件保护：急停、PL 租约、看门狗仍须独立存在。
- 规则过多、互相冲突时智能体会选择性遵守；每条规则应可检查（有文件、命令或数值可核对）。

## 来源与已验证的效果

- 规则逐条来自真实事故：按模式杀进程误伤自身会话、确认标记写错运行目录、早期结论被后续测量推翻等（见 [大模型协作记录](../../report/llm_collaboration.md)）。
- 本项目全程使用：机械臂上机运行、故障排查、PL 构建部署、文档与视频脚本均在这套规则下完成；新增规则用于后续检查与回归。
