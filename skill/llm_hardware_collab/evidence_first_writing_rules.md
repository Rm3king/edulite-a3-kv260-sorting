# 证据优先的写作规则

1. **先结论和数据，再讲机制。** 每个能力点回答三件事：做了什么、实测多少、证据在哪。
2. **数字只来自原始文件。** 文档里用占位符，由脚本从原始 JSON/CSV 渲染；同一数字在文档、指标表、图中只有一个来源。
3. **测量条件写全。** 硬件型号、模型与精度、输入规格、软件版本、时钟、次数或时长。
4. **口径分开。** 控制周期、视觉环延迟、整轮任务时长分别报告；关节跟踪误差与末端平稳度分别报告；不把不同条件的数字合成一个“加速倍数”。
5. **成功率写定义。** 写“成功次数 / 有效次数”，并写明成功、失败、人工干预的定义与统计范围。
6. **被推翻的结论直接撤回。** 不再引用，改用新的测量。
7. **失败分析单列一节。** 按“场景 → 已定位原因 → 已实施缓解 → 下一步”写，用事实陈述。
8. **缺数据就标注待补充**，继续写其余部分，不编造。
9. **文件命名**只用小写英文、数字、下划线、连字符。
