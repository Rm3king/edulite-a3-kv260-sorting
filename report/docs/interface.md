# 接口定义：协议、报文、寄存器与时序

主归属评分项：AI PC 与 FPGA/Zynq 协同（20）。

## 1. 分层

| 层 | 两端 | 载体 | 内容 |
|---|---|---|---|
| L1 作业通道 | AI PC → KV260 PS | SSH（密钥登录），专用 1 GbE，192.168.26.1 ↔ 192.168.26.2 | 内容寻址运行时（`releases/<sha256>`）、作业包、启动、事件轮询 |
| L2 视觉服务 | KV260 PS → AI PC | HTTP，端口 18768 + 零件序号 | 停顿对准：三帧 JPEG + 请求 → 修正/抓取段（≤ 8 MB） |
| L3 板内视觉环 | KV260 PS 进程间 | `/dev/shm/wvl_command.json`、`wvl_state.json`（原子替换）；相机服务 `127.0.0.1:8766` | 连续对准的命令、状态与帧 |
| L4 PS↔PL | KV260 | AXI-Lite MMIO（UIO 窗口 192 KiB：CAN `0xA0000000`，视觉核 `0xA0020000`）+ DMA | 轨迹段、心跳、修正目标、反馈、故障 |
| L5 PL↔电机 | KV260 PL | CAN 1 Mbps，29 位扩展 ID，SN65HVD230 | Type18 参数写（CSP，`0x7016`）、Type2 反馈 |

## 2. L1 作业通道

- 发布：文件逐个 gzip + base64，附 SHA-256；板端解包后逐文件校验，不一致即拒绝。
- 运行时：按源码内容摘要命名的目录 `releases/<sha256>`；相同内容复用，变更即新目录；启动前再次校验源文件摘要。
- 启动：`owner.json` 记录进程号与目录；`execution.log` 为事件流；主机轮询事件（`ONLINE_GRASP_TASK`、`CONTINUOUS_SERVO_END`、`JAW_OUTCOME` 等）。
- 失能确认：操作员确认承托后写 `SUPPORTED_DISABLE` 标记，板端据此完成失能。

## 3. L2 停顿对准服务（HTTP）

请求体绑定：`job_sha256`、`nonce`、`frame_sha256`、`iteration`、当前关节、已执行前缀；回复必须携带相同的 nonce 与摘要，否则丢弃。
回复分三类：MOVE（继续修正）、GRASP（进入抓取段）、RETURN（返回）。板端对回复的轨迹段再做限位、速度、加速度、电流与量化后检查，通过才执行。

## 4. L3/L4 板内：连续对准与 PL 寄存器

连续对准的命令（`run` / `freeze` / `stop` / `exit`）与状态（帧数、丢失数、误差、周期、逐帧轨迹）经两个小 JSON 文件交换；
PL 修正通道寄存器（`0xA0000000` 窗口内）：

| 偏移 | 名称 | 说明 |
|---|---|---|
| `0x840` | `ctrl` | bit0 使能；bit1 租约过期（只读） |
| `0x848` | `step` | 每 5 ms 最大变化（Q8.24 rad），上限 `0.003 rad` |
| `0x84c` | `lease_us` | 目标租约，上限 `500000 µs` |
| `0x850–0x864` | `targets[6]` | 六个关节偏移目标（Q8.24 rad），写入即续租 |
| `0x870–0x884` | `applied[6]` | 当前已施加偏移（只读） |
| `0x888 / 0x88c` | `writes / clamps` | 目标写入次数 / 被钳位次数 |
| `0x890` | `age` | 距上次写入的微秒数 |
| `0x894` | `id` | `0x43520001` |
| `0x898` | `rejects` | 被拒写入计数（非法写入被忽略并计数，不产生总线错误） |
| `0x8a0–0x8b4` | `limits[6]` | 每关节偏移限幅，上限 `0.25 rad`，运行中锁定 |

其余：`0x408` 微秒时基、`0x410` 心跳、`0x414` 租约（默认 100000 µs）、`0x418` 故障、`0x470` ABI 版本、`0x500+16·(id−1)` 反馈表、
`0x5a0/0x5a4/0x5a8` 许可/反馈超时/活动掩码、`0x800` 起为轨迹流寄存器（`0x820` 命令，`0x828` 能力字 `0x00070008`）、`0x900–0x9b0` 段暂存。
完整白名单与编码见 `board/software/canctl.py`。

## 5. L5 CAN 帧

Type18 参数写：CSP 模式（`0x7005 = 5`），位置 `loc_ref 0x7016`、速度限 `0x7017`、电流限 `0x7018`；Type2 反馈含位置、速度、力矩估计、温度、模式、故障。
Type18 的 `loc_ref` 采用 32 位浮点值；Type2 反馈中的位置字段采用 16 位编码，覆盖 ±12.57 rad。PL 每 5 ms 对七次多项式求值并发出设定。

## 6. 故障码与异常处理

| 来源 | 码 | 含义 | 动作 |
|---|---|---|---|
| `can_engine` | 1 / 4 / 8 | 租约过期 / 发送过期 / 反馈过期 | PL 停止 CAN 输出，`control=0` |
| `trajectory_stream` | 1 | 活动掩码不一致 | 停止轨迹流 |
| | 2 | 求值超过截止期 | 停止轨迹流 |
| | 3 | HLS 求值器拒绝 | 停止轨迹流 |
| | 4 | 守护（编码范围）失败 | 停止轨迹流 |
| | 6 | 修正后越出关节限位 | 停止轨迹流 |

主机侧：视觉请求超时 14 s；`bounded_reply` 32 s 内无有效回复则进入保持；板端对每个回复再校验。
保持状态下机械臂维持力矩，由操作员托住并在控制台确认后失能。

## 7. 时间同步与时序约定

- 图像到修正写入的延迟使用 **KV260 Linux 单调时钟**计时：从相机帧到达戳（`X-Board-Received-Monotonic-Ns`）到 ARM 写入 PL 目标，不依赖两台机器的时钟同步。
- AI PC 与板各自单调时钟；跨机报文用 nonce + 作业/帧哈希绑定防过期，不使用绝对时间戳。
- PL 内部时基为 32 位微秒计数器（`0x408`），租约、截止期、修正通道租约均以其为准。
- 跨机延迟以 RTT 报告（ICMP P50 0.169 ms，P99 0.25 ms，200 包，丢包 0.0%；见 `metrics/logs/comm_bench.json`）。
