# 本地视觉大模型：指令理解与执行结果复核

主归属评分项：AI PC 端侧 AI 能力（20）。

## 1. 指令理解

中文一句话指令先由规则解析（覆盖“数量 + 零件 + 目的盘”的规范句式，支持“大/小/M6/M12”“所有零件”“某类不要动”），
规则无法确定的句子交给本地 Qwen2.5-VL-3B（bf16，Radeon 890M，常驻进程），再由独立校验层检查：

- 输出必须满足任务合约（`workcell.task.v1`）：动作、步骤、数量、区域、目的盘字段与取值范围固定；
- 数量必须在句中出现，不允许模型补数；目的盘以句中所说托盘为准，不一致时纠正并记录；零件尺寸（大/小）以句中的零件词为准；
- 模型输出任务描述，包含类别、数量和托盘等字段；坐标、关节角与运动设定由规划和控制程序生成。

任务 LoRA（在 AI PC 上用 ROCm 训练）：160 步，312 s，可训练参数 1,843,200，峰值显存 8.0 GB；
合成留出措辞的 12 条用例：合约合法与语义正确由 11/12 提升到 12/12（`metrics/logs/task_lora_v2_report.json`）。

## 2. 执行结果复核（只读）

每轮任务结束后，控制台把以下材料交给同一个本地模型：

1. 执行前的源盘（右盘 A）图像与执行后的目标盘（左盘 B）图像（按托盘区域裁剪，保证小零件在模型输入里可见）；
2. 系统运行记录：每件零件的结果、放入的槽位、对准方式与用时、结束温度；
3. 头部相机检测（YOLO）统计出的目标盘零件数。

模型用中文给出 2–3 句复核说明；有未完成的零件时，依据记录中的原因解释并给出建议。生成约 10.2 s（P50，P95 12.1 s，15 次连续运行），
在机械臂回到承托位之后进行，不在控制环内，没有任何输出会回到运动指令。
零件**数量**取自 YOLO 检测，模型负责叙述与解释：3B 模型对小零件的计数不稳定，数量事实不交给它判断。

## 3. 控制台

`src/host/app/workcell/console.py`：一页完成“指令 → 理解 → 规划 → 执行进度 → 每件对准方式与用时 → 结果与复核”；
顶部显示零件检测运行在 NPU、大模型运行在 GPU（`metrics/evidence/console_four_classes_npu.png`）。
